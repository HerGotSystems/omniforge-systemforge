# Omniforge — System Forge™

Omniforge structures ideas, systems and campaigns into portable execution packages. It can hand those packages to the user's existing AI, or optionally execute them directly through a connected AI API.

Main app: [`app/index.html`](app/index.html) — open it directly in a browser, or serve it as a static file. No build step, no framework, no backend. Media Forge lives separately at [`app/media-forge.html`](app/media-forge.html).

For the PHUL licensing kit (the files at the repo root — `robots.txt`, `llms.txt`, `ai.txt`, `LICENSE-PHUL.txt`, `_headers`, `meta-tags.html`, `WELCOME.txt`), see [`LICENSE-PHUL.txt`](LICENSE-PHUL.txt). Those files are unrelated to the app below and apply to this repo the same way they apply to every other EMVY CHECK project repo.

## What it does

You describe what you want built. Omniforge assembles a strict output schema for the forge type you picked, then hands that off for execution under whichever mode you've chosen (below). Every forge returns a complete, structured package plus a mandatory **assumption audit** (what's being assumed, and the cheapest way to test each assumption) and **contradiction audit** (logical conflicts between sections).

## Execution modes

Omniforge does not require an AI API key to use. Three modes, selectable from the Forge pane or Settings:

### Default: Run With My AI
- No API key required.
- Omniforge prepares the exact structured RunPack packet — the same system + user prompt it would otherwise send — as copyable text (for ChatGPT, Claude, Gemini, or any AI you already use) or a downloadable JSON packet for another tool or agent.
- You run it wherever you like, then paste the result back into Omniforge to render it as a normal forge output, saved to history and clearly labelled **"Generated by Connected AI · via RunPack"** — distinct from the pre-run **"Prepared by Omniforge"** state, so it's never ambiguous whether an AI has actually produced anything yet.

### Optional: Connect AI API
- You may connect your own Anthropic API key to run forges automatically inside the app.
- Usage is billed to **your own Anthropic account** — a Claude.ai subscription does **not** include Anthropic API usage, and Omniforge never sees or receives your API charges.
- The key is **session-only by default**: it lives in `sessionStorage` and is gone once the tab closes. It is written to `localStorage` only if you explicitly check **"Remember this API key on this device."**
- If the connected account has no available credit, Omniforge shows a plain explanation and a one-click way back to Run With My AI or Settings — it never retries automatically or spends on your behalf.

### Future (not implemented): Omniforge Hosted
- An architecture slot exists for a future Omniforge-hosted execution provider (e.g. EMVY credits), so adding one later doesn't require restructuring the execution-mode dispatch.
- Not available yet — no billing or proxy has been built.

## The Forges

| Forge | Input | Output |
|---|---|---|
| **System Forge** | A raw idea or intention | Framework, assets, experiments, pilot plan, system sheet (+ deployment layer at Deep depth) |
| **Landing Page** | A product or service | Hero, problem, solution, social proof, pricing, CTA, SEO — full page copy |
| **Offer Builder** | What you're selling | Positioning, tiered pricing, objection handling, sales script, urgency/scarcity |
| **Content Forge** | A topic or angle | Hooks, article structure, distribution plan, repurposing plan |
| **Music Forge** | A mood or track idea | Suno/Udio prompts, production notes, release strategy, visual direction |
| **Rebrand** | A current, broken brand | Diagnosis, name options, identity, voice, launch plan |
| **Campaign Forge** | Product, goal, audience, offer, proof, CTA, channels | Campaign thesis, angles, hooks, video concepts + scripts + shot lists, per-platform copy, CTA variants, 7-day launch sequence, repurposing plan, visual asset recipe, filename checklist, Metricool-ready publishing package, RunPack execution packet |
| **Stress Test** | Any system or plan (yours or pasted) | Honest verdict, dangerous assumptions, failure modes, weakest link, kill tests, what's worth keeping, hard questions |

Campaign Forge works in both execution modes — Run With My AI (no key) and Connect AI API. It also has an optional **EMVY CHECK preset** that applies EMVY-specific framing rules (BUY IT / MAKE IT / USE IT, the Canvas Grid public/private distinction, accurate AI-in-workflow positioning) without hardcoding EMVY content into every forge.

## Media Forge

`app/media-forge.html` is a separate, single-file tool for turning images and optional audio into 9:16 / 1:1 / 16:9 assets with title/hook/CTA overlays and an end card. It requires no AI and no API key at all — it reuses EMVY CHECK's Living Art render engine (`app/lib/living-art-engine.js`) for seeded generative backgrounds, and exports PNG/WebM directly in the browser.

## Cross-cutting mechanics

These apply across every forge type, not just System Forge:

- **Lifecycle states** — `forged → stressed → reforged → ready`, tracked per output and shown in history.
- **Reforge** — feed in new information (a test result, a pivot, a constraint) and surgically update only the affected sections, without re-running the whole forge. In Connect AI API mode this runs live; in Run With My AI mode it prepares a Reforge RunPack (context + selected sections + current data) you paste into any AI, then paste the result back in to merge it.
- **Fork** — branch an output to explore an alternate direction while preserving lineage back to the original.
- **RunPack** — export any forge, or any post-hoc action (stress test, reforge, extend, assumption/contradiction extraction), as a portable JSON task packet you can paste into ChatGPT, Gemini, or any other model to continue the work outside Omniforge (bring-your-own-AI, no lock-in).
- **History** — every forge is saved locally (up to 100), with lineage (`derivedFrom` / `children`) between forks and stress tests, and tagged with its execution source (direct API vs. pasted-back RunPack result).
- **Export** — copy, or download as `.txt` / `.md`.

## Architecture

- `app/index.html` — the entire main application: markup, styles, and logic in one file. No build tooling, no framework.
- `app/media-forge.html` — the Media Forge tool, equally self-contained.
- `app/lib/living-art-engine.js` — the reused generative-art engine Media Forge draws on.
- Forge/history data (`omniforge_history`) is stored **locally in the browser** via `localStorage`. Nothing about a forge's content is ever sent anywhere except, in Connect AI API mode, a direct browser call to `api.anthropic.com`.
- An API key, if connected, lives in `sessionStorage` by default, or `localStorage` only when "Remember" is explicitly enabled — never on any Omniforge/EMVY server.
- Model ids are centralized in one `MODELS` config in `app/index.html` (currently Sonnet 5 default, Haiku 4.5 as a faster/cheaper option) — nothing else in the file hard-codes a model id.
- Adding a forge type means: an entry in `TOOLS`, a `buildXPrompt()` function returning the JSON schema, an entry in `SECTIONS_BY_TOOL`, and a dispatch line in `buildSysPrompt()`. Reforge, Fork, RunPack, lifecycle state, and export all work automatically for any forge that follows this shape, in both execution modes.
